# Split turn 压缩与恢复

实现移植自 `@earendil-works/pi-coding-agent@0.83.0` 的
`packages/coding-agent/src/core/compaction/compaction.ts`（[上游仓库](https://github.com/earendil-works/pi)，
[MIT 许可](licenses/pi-MIT.txt)，Copyright (c) 2025 Mario Zechner）。
保留 cpi 的裸 OpenAI 消息结构和自包含 JSONL compaction 节点，不引入上游会话格式依赖。

## 切分流程

从消息尾部估算约 `compaction.keepRecentTokens` 的原文预算（默认 20,000），
切分点只能落在 user 或 assistant 消息之前。工具结果不能单独成为保留后缀的起点；
assistant 的全部工具调用与对应结果必须一起保留或一起摘要。

若切分点落在用户回合中间，回溯到该回合的用户消息，分成三个互不重叠的部分：

```text
此前历史                  当前回合前缀                   当前回合后缀
历史问题与回答            本轮用户要求、早期工具执行     最近的完整工具轮
      ↓                           ↓                           ↓
结构化历史摘要            回合前缀摘要                   保留原文
      └────────── 合并摘要 ────────┘                           │
                         └──────── 新上下文 ──────────────────┘
```

历史摘要延续已有 `previousSummary`。回合前缀使用上游的三个关注点：
`Original Request`、`Early Progress`、`Context for Suffix`，随后以
`**Turn Context (split turn):**` 合并进摘要。保留后缀不再重复发送到摘要请求。

未切开回合时只生成历史摘要。只有一个大回合、没有旧历史时只生成前缀摘要。
系统提示独立保留，不参与历史压缩或用于识别用户回合。

## 自动、手动和超限恢复

三条路径共用 `compactContext` 和安全切分计划；超限恢复不再直接保留最后 5 条消息。
会话存在时均写入同一种 compaction 检查点，包含合并摘要、`retainedTail`、
`isSplitTurn`、`reason`（`auto` / `manual` / `reactive`）、摘要输入指纹及用量。

空尾巴也写 `retainedTail: []`，确保重新打开时不会重新带入已被摘要的原文。
旧 JSONL 会话仍可读取，不要求新增字段。模型和思考参数从整条活动分支恢复，
不随旧消息压缩而丢失。

无会话路径保存完整 `.transcripts/` 快照后，返回相同的“摘要 + 安全原文尾巴”视图。
L3 仍使用 2000 个估算 Token 的落盘阈值和约 500 Token 的预览预算。

## 调用成本与失败语义

- 历史和回合前缀均存在时，通常需要两次摘要模型调用；只存在其中一部分时需要一次。
- 两次响应的 usage 和成本合并到同一个检查点，分别计入共享请求预算。
- 摘要复用指纹覆盖两份完整 prompt、旧摘要以及模型；复用合并摘要时不重复调用模型，
  但分支自己的保留后缀仍重新保存。
- 两份摘要完成前不修改原上下文，不写部分检查点。任意调用失败或用户取消，保留原状态。
- 压缩期间分支或会话叶节点变化时拒绝提交旧计划，避免覆盖新分支内容。
- 工具调用未闭合或存在孤立工具结果时拒绝压缩；应先恢复合法回合或检查执行记录。

## 与上游的适配差异

- cpi 用 `retainedTail` 保存原文快照，上游以 `firstKeptEntryId` 引用会话节点。
- 预算沿用 cpi 的模型窗口、输出预留和字符启发式估算，允许安全切分边界造成预算偏差。
- 保留 cpi 强制 `/compact` 的行为：短历史也会尝试摘要旧部分，尽量保留最近用户回合；
  这不同于上游在没有可摘要前缀时直接跳过的行为。只有摘要占位、没有新增对话时跳过。
- 如果最新完整工具轮本身大于原文预算，优先保留工具配对，不能承诺上下文一定缩减到预算内。
- 保留单次 agentLoop 中超限恢复最多一次的限制；这次移植没有新增完整自动压缩熔断器。
