# 并发工作区隔离与恢复

代码入口：`workspaces.ts` 管理绑定，`repository-lock.ts` 管理仓库锁，
`file-transactions.ts` 管理文件事务；任务、子 Agent 和进程工具统一接入这些入口。

## 认领与身份

任务创建、编号分配、依赖校验在看板锁内完成。读取任务不再重写反向依赖索引。
认领顺序是 `pending → preparing → 创建并验证 Worktree → in_progress`。
Git 不可用、目录或分支不匹配、创建失败都会拒绝认领，不降级到主目录执行。
记录准备进程和创建时的基线 SHA；退出进程遗留的准备状态会在下次认领时核验。
已有执行记录则保留原归属；只有没有执行记录且目录无代码改动时才恢复为待办。

任务 Worktree 位于 `.agent/worktrees/task_<n>/`，分支为 `agent/task-task_<n>`，
基线来自认领时的已提交版本。任务创建入口现在返回 Promise，SDK 调用方必须 `await`。

工作区记录保存于主工作区 `.agent/workspaces/records/<UUID>.json`，另有按 Agent
身份索引的记录。包含任务、仓库标识、目录、分支、基线 SHA、代次、进程身份和状态。
每次写入核验记录、归属、代次、分支和实际路径，并拒绝修改 `.git`、`.agent` 控制数据。
路径别名也按实际目标校验。

主 Agent 使用会话 ID 作为稳定身份，不同会话不会共用一个默认 owner；无会话调用采用
进程内的随机身份。队友使用运行时 Agent ID，手动和 idle 自动认领一致。
Workdir 上下文覆盖队友的整个 WORK/IDLE 生命周期，Loop 入口重新核验、恢复绑定。
恢复不会接管其他存活进程的工作区，也不会凭旧 PID 终止进程；失去归属的旧代次不能写入。

## 一次性 Worker

`worker` 和可写的通用 `subagent` 自动创建独立 Worktree。调度器在仓库锁内使用
临时 Git index，捕获父目录当前的已跟踪文件和非忽略的新文件，包括暂存与未暂存修改、
二进制文件、删除和执行权限。不修改用户的 index、主分支或 HEAD。
运行数据、依赖目录和常见凭据文件不进入快照；符号链接等非普通文件会拒绝快照。
内容由 Git 流式计算对象，不把大文件整块读入 Node 内存。

Worker 的私有基线 commit 和分支记录于 Git；目录为
`.agent/worktrees/worker-<UUID>/`。输出只包含相对于私有基线的差异，避免再次交付父目录
已有的脏改动。成功完成时由协调者核验并整合到父工作区；发生冲突或失败时保留产物。
原文产物、二进制 patch 和 manifest 位于 `.agent/artifacts/<workspace-id>/`，
父会话有 `worker_artifact` 审计记录。失败或未合并的内容不会被强制删除。

父任务不能在子 Worker 仍 active 时交付。Worker 结束时取消并等待本次启动的后台进程，
然后保存产物；未知执行状态不会被当作已停止。

## 写锁与整合

同一仓库的所有 Worktree 以规范化 `git-common-dir` 识别仓库，使用共同的 writer 锁。
顺序为仓库锁、看板锁、单任务锁。文件编辑、检查点恢复、产物整合、快照及受控 Git
操作遵守此顺序。Linux 使用系统 `flock`，持有进程退出后锁自动释放；其他平台保留
`proper-lockfile` 后端，异常退出后可能需要等待 stale 超时，未宣称同等崩溃恢复时延。

整合先验证全部目标的基线哈希、执行权限和产物完整性，再应用；冲突拒绝覆盖，不自动
三方合并。整合与任务状态更新在仓库锁内串行执行，不自动提交、不改变暂存区。
整合旧任务不会清掉 Agent 正在处理的新任务绑定。

普通主 Agent 的非隔离 Shell 和验证命令也持有仓库锁直到执行结束，后台命令相同。
这保证 cpi 的这些入口不会同时整合或编辑主目录，但长命令会阻塞其他写入；建议把
长时间验证委派到独立工作区。

## Shell 与运行边界

可写工作区的 Shell 和验证命令必须使用 Linux bubblewrap：仅自己的目录可写，
共享 Git 元数据与依赖只读，其他工作区不挂载，私有运行数据隐藏，临时目录和 PID
命名空间独立，网络隔离。命令不能通过共享 Git 引用绕过隔离。
缺少 bubblewrap 或系统不允许创建命名空间时命令失败，不退回普通 Shell。

Worker 可以继续通过内置文件工具编辑代码。需要更严格的主 Agent 行为时启动：

```sh
CLAUDE_PI_ISOLATION=required cpi
```

此时主 Agent 也必须先认领任务或委派 Worker，才能修改文件或执行命令。
普通模式的主 Agent 是可信协调者；仓库锁不是对任意宿主代码的 OS 沙箱。
项目扩展、Hooks、远程 MCP 和外部服务仍有各自的信任与副作用边界，不能借文件快照
保证它们的任意操作可回滚。用户编辑器也不会自动遵守 cpi 的锁，仍需版本检查。

## 文件事务与重启恢复

写入前保存原始字节与模式的检查点，再写入并 fsync
`.agent/transactions/<UUID>.json`。日志记录每个目标的前后哈希、模式和检查点 ID。
文件及目录变更落盘后才标记 committed。可捕获失败会逆序回退，包含刚写入但后续步骤
失败的当前文件；进程被强制终止时，下一次 Loop、编辑或整合先处理未完成日志。

恢复先核验全部文件和检查点。当前内容必须仍是写前或预期写后版本；检测到用户后续
改动时保留冲突并阻止新的写入，不覆盖用户内容。日志用于恢复文件事务，并非整个
Agent 任务的自动撤销：正常完成的编辑仍使用 `restore_checkpoint`，数据库、部署等
外部副作用不包含在文件恢复内。

## 验证

`tests/workspace-isolation.test.ts` 使用独立临时仓库、真实子进程和本地 HTTP mock，
覆盖多进程编号与认领、隔离失败、旧代次/重定向目录、存活进程保护、退出后的恢复、
idle 跨轮绑定、父子交付、父目录脏文件快照、主目录编辑与整合竞态、强制终止后的
恢复、用户冲突保留、当前文件回退、后台进程和 Worker 模型/工具往返。
不调用付费模型。

本机此前的 bubblewrap 探测失败。因此本机验证了参数构造和拒绝/无副作用路径；
沙箱成功运行时的完整隔离还需在允许 bubblewrap 命名空间的 Linux 主机验证。
